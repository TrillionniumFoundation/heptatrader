## Program and failure behavior

- prospective_multihorizon.py register: creates a new root, exact
  Phase 3 local preregistration, SHA-pinned plan and time slots,
  immutable/no-effect campaign.json. A second registration under
  the same path is denied.
- capture --slot N: only within that slot's declared narrow time
  window, independently revalidates source configuration, original
  account period, frozen cost, source and exactly registered plan,
  then seals one original as-of input with all future labels PENDING.
  Duplicate, late, expired, pre-registration-only, manipulated
  source path and changed frozen code are rejected.
- status: reports full FIXED declared slot denominator, separating
  not-due, open/uncaptured, exact sealed input and MISSED_NO_OPERATOR_CAPTURE.
  The last category is explicitly NOT a claim the market had no quote.
- The separate prospective_horizon_observe.py provides a READ-ONLY
  on-demand price outcome observer. It refuses to run before each exact
  maturity plus a fixed five-second grace, preserves original sealed
  input identity, waits until independently read original NUMERIC
  source segments are sealed through maturity, and then writes one
  create-once price-only observed or censored receipt. This is NOT an
  independently signed evaluator or a financial PnL outcome.
- There is no automatic capture watcher or scheduled follow-up
  processing. Actual separately controlled product evaluator identity,
  complete quote-path proof, and the no-trade economic comparator
  remain mandatory before reporting an economic qualified outcome.
