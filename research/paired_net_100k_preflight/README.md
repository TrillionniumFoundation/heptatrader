# Current USD100k Laya English vs mmBERT feature preparation

This module is a **read-only engineering preflight**. It does not train a
financial head, retroactively predict a trade, evaluate a profit, route a model,
mint Agentd admission, call IB/TWS, modify a strategy, or submit an order.

A trusted immutable EUR.USD PAPER producer must have exactly the original
`EURUSD_ORIGINAL_ENTRY_CONF_0.62_USD100K_REFERENCE_NOTIONAL` profile, the
current period digest and its original attribution source-chain identity.
Every available original flat-position input is included in chronological
order, not chosen for a favorable direction or outcome. Duplicate or mutated
request hashes fail. Six authenticated current-producer flat-position inputs
existed at the first actual 2026-10-08 engineering run.

BUY and SELL conditionals are computed from the same authentic input before
seeing any response, commission, realized PnL, subsequent PREPARED integer EUR
quantity or its later executable reference quote. The fixed 100000 USD budget
was known from the original behavior policy and is included in each feature.
Output never contains the original plaintext input, only a private tokenized
feature store and a hashed map back to its source prefix.

Both **complete** official base model checkpoints, tokenizers and encoder
configurations are pinned to previously verified upstream immutable SHA256
inventories. Load uses strict state dictionaries. The model parameters are
frozen. Each same UTF-8 conditional text is independently tokenized without
truncation, refusing any example over 2048 tokens.

Masked mean L2 representations retain actual pretrained widths, 768/mmBERT
and 1024/English. A further deterministic fixed non-trained projection
produces 256D for a **capacity-controlled future head** experiment. Equal
head width does not establish representation parity or predictive advantage.
Files and row vectors carry SHA256 identity receipts and are re-verifiable
without invoking the original mutable runtime.

The GPU worker enters Landlock+seccomp before loading Torch. No broker bearer,
outside-output writes or new socket operations are available. Do not run this
tool to produce predictions for historical requests: features computed after
their original request times are *not prospective commits*. The actual source
is a memory of historic inputs, never a synthetic monetary reward.

# Strict financial A/B admission

At least two distinct, precisely attributed, fully closed, fee-complete USD100k
behavior rewards are the minimum engineering-training entry point, **not**
evidence of generalization. The old EUR25k/hysteresis producer, floating PnL,
zero-fill attempts, later inferred direction and revoked/corrected labels never
count. Complete money economics are independently replayed and identity-bound.

Only after labels exist can two separate heads be fitted on exactly the same
original reward IDs and request/action inputs, with no actor policy gradient.
An independent frozen 14-day future window plus 1-day closure allowance and
the existing financial-forward strict null/e-test/fee-stress protocol is still
required. A preflight encoder cache cannot be substituted as a past trial.
No model may receive trading authority without separate canonical Agentd owner
enrollment and independent prospective qualification.

A future upstream-source comparison must be run in a separately bounded,
broker-level *read-only* data session. TWS/IB Gateway API Read-Only must not be
enabled on the existing order-executing gateway because that changes order
permissions. Source timestamp freshness, path/endpoint coverage and identity
must be verified before any new Fusion prospective window. The previous
17/24 REJECTED Fusion window remains unchanged.
