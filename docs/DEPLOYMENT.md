# Minimal runtime deployment

Status: current Simulator/Agent install implementation; PAPER host deployment remains separately validated
Applies to: `cmake/RuntimeInstall.cmake`, `systemd/`, `sysusers.d/`, `tmpfiles.d/`
Verification: `canonical-full-suite` install smoke on the exact revision; target-host checks are separate

The repository provides one small `runtime` install component. It assembles the deterministic Simulator/Gateway path and MCP client adapter without restoring release bundles, evidence closure or host certification.

## Build and install

For a system installation, configure the intended prefix before generating the systemd units:

```bash
cmake --preset core-release -DCMAKE_INSTALL_PREFIX=/usr
cmake --build --preset core-release --target hepta_runtime_binaries
sudo cmake --install build/core-release --component runtime
```

Installed objects include:

- `hepta-tool-gatewayd` and `hepta-executiond` under the configured libexec directory;
- `heptactl`, `hepta-sessionctl` and `hepta-agent-mcp-launcher` under the configured bindir;
- the MCP bridge, Codex plugin metadata, fixed Simulator/Gateway systemd units;
- sysusers/tmpfiles declarations, examples and current runtime documentation.

The generated service files contain the exact configured executable and documentation paths. Do not configure with `/usr/local` and later copy only the unit files into a `/usr` deployment.

## Installed research runner

The runtime component includes `share/heptatrader/research/run_protocol.py`,
its side-effect-free `protocol_support.py` helper, the current static manifest
and the research schema.  It intentionally does
not install the experimental strategy source assets referenced by the static
manifest.  Use the installed runner's `self-test` or supply a complete
`RunManifest` to `run`/`replay`; verify the checked-in static manifest from a
source checkout (or pass that checkout through `verify --root`):

```bash
/usr/local/share/heptatrader/research/run_protocol.py self-test
/usr/local/share/heptatrader/research/run_protocol.py verify \
  --manifest /usr/local/share/heptatrader/research/manifest-v1.json \
  --root /path/to/heptatrader
```

When those source assets are unavailable, verification returns
`RESEARCH_STRATEGY_INPUT_MISSING` and a non-zero exit status.  Missing research
inputs are never interpreted as a passing install check.

## Host prerequisites

Create runtime identities and directories:

```bash
sudo systemd-sysusers /usr/lib/sysusers.d/heptatrader.conf
sudo systemd-tmpfiles --create /usr/lib/tmpfiles.d/heptatrader-agent-os.conf
```

Copy and review examples into `/etc/heptatrader`:

```text
hepta-tool-gateway.env
hepta-execution-simulator.env
trust-domains/uid-<agent-uid>.json
```

Provision private credentials separately:

```text
/etc/heptatrader/hepta-supervisor-lease.key
/etc/heptatrader/credentials/hepta-execution-simulator-fence
/run/hepta-agent/session.token or the configured trust-domain token path
```

Credentials are not installed or generated by CMake. Missing or unsafe credentials must make the service fail closed.

## Simulator startup

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now \
  hepta-execution-simulator.socket \
  hepta-execution-events-simulator.socket \
  hepta-tool-gateway.socket \
  hepta-tool-session-supervisor.socket
sudo systemctl enable --now \
  hepta-execution-simulator.service \
  hepta-tool-gateway.service
```

Check:

```bash
systemctl status hepta-execution-simulator.service hepta-tool-gateway.service
heptactl system.get_health
```

## MCP / Codex

The installed plugin invokes `hepta-agent-mcp-launcher` through the host PATH. The launcher derives the MCP server path from its installation prefix, verifies root ownership/mode and then supplies only the reviewed socket, token and UID environment.

Every mutually untrusted Agent requires its own OS identity, trust-domain config, socket/session token and capability set. Installing the plugin does not grant PAPER or LIVE authority.

## Staged install smoke

CI can verify the tree without mutating the host:

```bash
stage="$(mktemp -d)"
DESTDIR="$stage" cmake --install build/core-release --component runtime
find "$stage" -type f -o -type l
```

A successful install-tree smoke proves file assembly only. Target-host users, credentials, systemd behavior, network policy and IB PAPER still require explicit environment-specific validation.
